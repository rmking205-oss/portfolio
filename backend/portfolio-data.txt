## PROJECT 1: QUIZ BIO SYSTEM

Project Type:
Independent Project

GitHub Repository:
https://github.com/rmking205-oss/quiz-bio-system.git

Description:
Quiz Bio System is a web-based online assessment application focused on conducting controlled quizzes while adding student identification, biometric verification and anti-cheating mechanisms.

The project combines a traditional multiple-choice quiz system with browser monitoring and face detection features.

Technologies:

* HTML
* CSS
* JavaScript
* Face API
* Browser APIs

Main Purpose:
The main purpose of the project is to create a controlled online quiz environment where students can be identified and monitored during an assessment.

Main Features:

* Student identification
* Student name input
* Student username input
* Student email input
* Multiple-choice questions
* Timed quiz
* Five-minute assessment timer
* Question navigation
* Progress tracking
* Automatic submission
* Face detection
* Face landmark detection
* Face recognition
* Face descriptor generation
* Webcam access
* Identity verification
* Tab-switch detection
* Violation tracking
* Anti-cheating mechanisms
* Right-click prevention
* Copy and paste prevention

How It Works:
The student provides identification information before starting the quiz.

The application then loads the quiz questions and starts the assessment timer.

JavaScript manages the quiz state, question navigation, answer selection and submission process.

Browser visibility events are monitored to detect when the student switches away from the quiz.

The application tracks violations and can automatically submit the quiz when the allowed violation limit is exceeded.

The webcam can be accessed through the browser to capture the student's face.

Face API models are used for face detection, facial landmarks and face recognition.

The system can generate and compare face descriptors to help verify student identity.

Challenges:
One of the main challenges was combining quiz functionality with security and monitoring features while keeping the application usable.

Another challenge was implementing webcam access and face recognition correctly in a browser environment.

Monitoring browser activity and maintaining quiz state also required careful JavaScript event handling.

I designed and developed the project independently.

* Application state management

What I Learned:

## PROJECT 3: STUDENT MANAGEMENT SYSTEM

Project Type:
Independent Project

GitHub Repository:
https://github.com/rmking205-oss/student-management-system.git

Description:
Student Management System is a full-stack application for managing student records through a web-based backend system.

The project combines Express.js with MySQL for student data management and MongoDB for recording system activities.

Technologies:

* Node.js
* Express.js
* MySQL
* MySQL2
* MongoDB
* MongoDB Atlas
* REST APIs
* JavaScript

Main Purpose:
The purpose of the project is to provide a backend system for creating, viewing, updating and deleting student records.

Main Features:

* Add students
* View students
* Update student records
* Delete students
* Student ID management
* Student name management
* Student email management
* Student course management
* REST API endpoints
* Activity logging
* MongoDB activity storage

How It Works:
Student information is stored in a MySQL database.

The Express.js backend provides API endpoints for managing student records.

A student can be created using the API, retrieved from the database, updated and deleted.

Important actions are also recorded in MongoDB as activities.

The activity system records operations such as:

* student_added
* student_updated
* student_deleted

Database Structure:
MySQL is used for the main student records.

MongoDB is used for activity logging.

This demonstrates the use of two different databases for different purposes within the same application.

Environment Configuration:
The application uses environment variables for database connection information instead of hardcoding sensitive connection details.

AI CHATBOT
==========

LLM Used:
GPT-OSS-120B through Groq.

RAG System:
The portfolio chatbot uses a Retrieval-Augmented Generation (RAG) approach.

Portfolio information is stored in portfolio-data.txt.

When a user asks a question, the system searches the portfolio knowledge base for relevant information.

The retrieved information is then provided to the language model as context.

The language model generates a natural-language response based on the retrieved portfolio information.

Chatbot Knowledge Scope:
The chatbot should primarily answer questions related to:

* About me
* Skills
* Technologies
* Independent projects
* Contribution projects
* Project features
* Project technologies
* Project contributions
* Project challenges
* What I learned
* APIs
* Databases
* Backend development
* Frontend development
* Git and GitHub
* Development experience
* Portfolio information

Important Chatbot Rule:
The chatbot should use the portfolio knowledge base as its primary source of information.

It should not invent project features, technologies, contributions, experience or achievements that are not supported by the portfolio information.

When a requested detail is not available in the knowledge base, the chatbot should clearly say that the information is not available rather than making up an answer.
